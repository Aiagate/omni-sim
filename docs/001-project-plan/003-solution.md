## ⚙️ 推奨ソリューション分布マップ（Phase 3更新版）

| 層     | 処理モデル                    | 推奨技術・実装手法              | 備考                             | Phase |
| :----- | :---------------------------- | :------------------------------ | :------------------------------- | ----- |
| 銀河層 | **静的Graph**                 | `networkx`, `numpy`             | 航路と星系間距離をキャッシュ保持 | 1-2 ✅ |
| 国家層 | **並列Actor**                 | `Ray` の `@ray.remote` クラス   | 国家ごとにAIを独立スレッド化     | 3D   |
| 艦隊層 | **ECS更新＋バッチ処理**       | Numba or Bevy構造               | 毎tickで位置/燃料/戦闘を一括更新 | 1-2 ✅ |
| 経済層 | **行列演算バッチ処理**        | `NumPy` + `NetworkX` + `scipy`  | 物価計算・市場均衡を高速演算     | 3A 🎯 |
| 輸送層 | **離散イベント駆動（SimPy）** | SimPyでイベントキュー制御       | 個別輸送船団の詳細追跡           | 3C   |
| 人口層 | **統計近似 / 集約更新**       | NumPy配列操作 or pandas groupby | 「1都市=代表値」などで縮約       | 4    |

**Phase 3実装優先順位**:
- **3A (最優先)**: 経済層 - 行列演算による大規模シミュレーション（詳細は `docs/003-economic-solution.md`）
- **3B (重要)**: 星系間移動システム
- **3C (推奨)**: 輸送層 - SimPyによる詳細物流シミュレーション
- **3D (拡張)**: 国家AI - Ray並列処理

## 🧠 階層間の相互作用イメージ

```
[銀河ネットワーク]
     │
     ├─ 国家AI (Ray Actor)
     │     └─ 経済政策・軍事戦略決定
     │
     ├─ 艦隊ECS (Numba高速更新)
     │     └─ 艦隊移動・戦闘・補給
     │
     ├─ 輸送SimPy (イベント駆動)
     │     └─ 到着時に資源を更新し国家層へ反映
     │
     └─ 人口統計 (NumPyベクトル更新)
           └─ 生産・消費データを経済層に提供
```

こうすることで：

* **国家AI層** は重い思考処理を並列で
* **艦隊/輸送層** は大量オブジェクトをECSで効率的に更新
* **人口層** は集約更新（統計モデル）でCPU節約

という **「粗粒度はActor、細粒度はECS、さらに細かい層は統計近似」** という構造になります。
これが大規模シミュレーションを現実的に成立させる黄金パターンです。

## 🧩 速度階層設計（時間ステップの分離）

各層ごとに「更新頻度」を分離すると効率が跳ね上がります。

| 層     | 時間解像度   | 更新間隔      | 例                     |
| :----- | :----------- | :------------ | :--------------------- |
| 銀河層 | 年単位       | 1000tickに1回 | 航路変動や星系滅亡など |
| 国家層 | 週単位       | 7tickに1回    | 政策変更、外交         |
| 艦隊層 | 日単位       | 毎tick        | 航行・戦闘             |
| 輸送層 | イベント単位 | イベント時    | 輸送完了時のみ         |
| 人口層 | 月単位       | 30tickに1回   | 成長率・労働力変化     |

➡️ **すべてを毎tick更新しない**。
重要な層だけを高頻度更新、他は緩やかに反映することで、
1日で「1か月」どころか**数十年分**をシミュレーション可能になります。

## 🧮 データ構造最適化の考え方

| 層   | データ構造                          | 説明                     |
| :--- | :---------------------------------- | :----------------------- |
| 銀河 | Adjacency matrix / CSR graph        | 航路距離計算をキャッシュ |
| 国家 | Dataclass or Pydantic model         | 明確な属性管理           |
| 艦隊 | NumPy structured array              | SIMD対応でベクトル更新   |
| 輸送 | PriorityQueue (SimPyイベントキュー) | 到着時刻順に処理         |
| 人口 | Dense array (NumPy)                 | ベクトル更新で高速       |

---

## 💾 データ保存・再現

* 毎tickログではなく「国家レベル＋イベントログ」に限定
  → 例：「国家間貿易量」「戦争勃発」「惑星消失」などのみ保存
* 内部ステートをSQLiteやParquet形式で保存
* 再生時には必要なtick範囲のみ再構築（＝タイムスライス）
