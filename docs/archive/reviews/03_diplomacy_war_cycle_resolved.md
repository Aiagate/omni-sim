# Deep Dive: 外交と戦争の循環 (Diplomacy & War Cycle)

## 現状の課題

`systems/war.rs` と `systems/diplomacy.rs` の連携が弱く、以下のループが発生する可能性があります。

1.  外交スコアが -50 を下回る → **宣戦布告 (AtWar付与)**
2.  戦争で双方が消耗、または15 Tick経過 → **停戦 (AtWar削除)**
3.  外交システムが走る。スコアは -50 以下のまま（あるいは戦争中の信頼度低下でさらに悪化している）。
4.  次の Tick の戦争システム → **即座に再宣戦布告**

これでは停戦の意味がなく、どちらかが滅びるまで終わらない戦争になります。

## 改善案

### A. 停戦時の関係リセット

停戦 (`Ceasefire`) イベント発生時に、強制的に外交関係を「戦争直前」の状態まで引き上げる。

*   `DiplomaticRelation.score` を `-40` (戦争トリガーの少し上) に設定。
*   ただし、信頼度 (`NationalMemory`) は回復しないため、放っておくとすぐにまた下がる（不安定な平和）。

### B. 停戦条約 (Truce) 期間の導入

`DiplomaticRelation` または `Nation` に「停戦期間 (Truce)」データを保持させる。

```rust
pub struct Truce {
    pub with_nation: Entity,
    pub until_tick: u64,
}
```

*   `war_trigger_system` は、`Truce` 期間中の相手には（スコアがいくら低くても）宣戦布告できない。
*   Truce 期間中に外交官（Diplomacy System）が関係修復を試みるチャンスが生まれる。

### C. 戦争疲弊 (War Exhaustion) の導入

Paradox社のゲームのように、国家に「戦争疲弊度」を導入する。
戦争中、時間経過や損害とともに上昇し、これがあまりに高いと（国民の反発等で）宣戦布告ができなくなる、あるいは強制的に和平モードになる。

## 推奨方針

実装コストと効果のバランスから、まずは **B案（停戦条約期間の導入）** を推奨する。
これにより、システム側で確実に「平和な期間」を保証でき、その間に外交スコアを変動させる余地が生まれる。
