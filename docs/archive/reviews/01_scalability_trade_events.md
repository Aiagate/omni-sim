# 深掘り分析: スケーラビリティ (貿易・イベント)

## 1. 貿易システムの計算量問題

### 現状分析
現在の `trade_system` ([src/systems/trade.rs](file:///home/dorothy/repos/omni-sim/src/systems/trade.rs)) は以下の構造になっています。

```rust
for route in &trade_routes { // 全貿易ルートのループ
    // ...
    // 惑星から国家を逆引き
    let from_nation = nation_query.iter().find(|(_, b)| b.0 == route.from_planet);
    let to_nation = nation_query.iter().find(|(_, b)| b.0 == route.to_planet);
    // ...
}
```

- **問題点**: 貿易ルートごとに全国家エンティティを走査 (`find`) しています。
- **計算量**: 貿易ルート数を $R$、国家数を $N$ とすると、$O(R \times N)$ です。
- **影響**: 惑星数 $P$ に対して全結合の貿易網がある場合 $R \approx P^2$ となり、全体で $O(P^3)$ に近い計算量になります。数十惑星の規模でシミュレーションの Tick 速度が顕著に低下します。

### 改善案
1. **反転インデックスの導入**:
   惑星エンティティから国家エンティティを即座に引ける `Resource` または `Component` (例: `PlanetToNation(HashMap<Entity, Entity>)`) を導入し、検索を $O(1)$ にします。
2. **空間インデックスによるルート制限**:
   全惑星間の貿易ではなく、一定距離内の惑星間のみに限定する、あるいは「星系間ゲート」のようなハブを通じた貿易構造にすることで $R$ 自体を抑制します。

## 2. シミュレーションイベントのオーバーヘッド

### 現状分析
[simulation_event.rs](file:///home/dorothy/repos/omni-sim/src/components/simulation_event.rs) を用いたイベント駆動型の構成は、ドメインと表示の分離には適していますが、粒度が細かすぎる可能性があります。

- **問題点**: 1つの貿易ルートで発生する「資源ごとの移送」が個別の `SimulationEvent::TradeTransfer` として送出されています。
- **影響**: 
    - **メモリ/CPU**: 1 Tick あたり数千〜数万のイベントが発行されると、Bevy のイベントキューのメモリ消費と、それを読み取る `tui_event_collector_system` のリソース消費が無視できなくなります。
    - **TUI/表示**: 大量のログイベントを TUI で全て受け取ると、スクロールバッファの肥大化や描画の遅延を招きます。

### 改善案
1. **イベントのバッチ化**:
   `TradeTransfer` イベントを「ルート単位」または「Tick単位の集計値」として送出するように変更します。個別の移送詳細は、必要な場合のみ（例: ユーザーが特定の惑星を注視している場合）発行するオプションを設けます。
2. **重要度フィルタリング**:
   シミュレーションイベントに `Importance` レベルを付与し、CLI/TUI側で設定したレベル以下のイベントはドメイン側でそもそも発行しない（または即座に破棄する）仕組みを導入します。

## 3. 実装後の課題と次なる改善

レビューの結果、以下の項目が今後の改善対象として特定されました。

### 1. インデックスの整合性確保
現状の `update_nation_planet_index_system` は新規追加と変更には対応していますが、国家が惑星を失った際（削除）のインデックス更新が不完全です。惑星の割譲や喪失が発生するフェーズでは、`RemovedComponents` を監視してインデックスをリビルドする、あるいは部分的な削除ロジックを実装する必要があります。

### 2. 重要度に基づく汎用フィルタリングの実装
`EventImportance` は導入されましたが、現状は各出力プラグイン（CLI/TUI）が個別に表示可否を判断しています。`SimulationConfig` に `min_importance` などの設定を追加し、ドメイン側またはイベントバスのレイヤーで一括フィルタリングすることで、大規模シミュレーション時の負荷をさらに最適化できます。

### 3. レガシーイベントのクリーンアップ
`TradeSummary` によるバッチ化が完了したため、用途が重複する `SimulationEvent::TradeTransfer` の廃止を検討します。特定の惑星を詳細にデバッグしたい場合などの「詳細ログモード」が必要ない限り、コードの簡素化のためにこれらを整理します。
